# Fair admission across cooperating tool servers

All Luda operations still return `BUSY` immediately when they cannot run. A per-display FIFO ticket registry prevents a fast previous owner from repeatedly acquiring the display ahead of waiting clients. `BUSY` includes `queued`, `queue_position`, `retry_after_ms` (100), and `priority_lease_ms` (2000 when queued). Retry explicitly within the lease to retain priority. The tool does not retain operation arguments, perform an automatic retry, or replay input; target freshness is checked only when the requested operation actually executes.

Fairness is cooperative and conditional on retrying before the lease expires. It does not guarantee operating-system scheduling or exclude software that bypasses Luda admission. The arbitration lock itself is nonblocking; a client contending for that brief lock receives unqueued `BUSY`. A client's retries refresh its expiry without changing its FIFO position. Idle tickets expire after two seconds; process death and PID reuse remove tickets immediately on the next admission attempt. Expiry uses suspend-aware elapsed time and prior-boot tickets are discarded. At most 64 client tickets and 32 KiB of state are accepted. A full queue reports unqueued `BUSY` instead of hiding a ticket or waiting indefinitely.

The arbitration lock is held only while updating the ticket registry and attempting the existing nonblocking display flock. It is never held while driving the desktop. The display flock remains the exclusive-operation authority and is automatically released if its process dies. Cancellation removes the client's ticket where the registry is available; if the registry is simultaneously busy, its lease bounds residual reservation. Successful admission consumes the ticket. Cancelling a ticket never cancels another client's action.

Registry files are regular, single-link, mode-0600 files in the account's private mode-0700 runtime directory. Reads have a fixed byte bound; writes atomically replace the state under a separate lock. Symlinks, FIFOs, hard links, malformed state and unsafe permissions are refused before admission. The registry contains only client nonce, PID/start identity and lease expiry, never application names, screenshots or input text. Another account cannot read or alter the private state; hostile same-account processes remain outside the X11 isolation boundary.

`tests/test_admission.py` verifies FIFO despite repeated reacquisition attempts, explicit bounded queue/full responses, lease refresh and idle expiry, cancellation before/after locking, malformed and unsafe files, PID reuse and boot replacement. A real multiprocess protocol independently verifies FIFO, mutual exclusion, queued-client death, and owner-crash lock recovery without a graphical display.
