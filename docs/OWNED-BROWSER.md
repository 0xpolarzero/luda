# Optional temporary owned browser

`desktop_open_browser(url, lifetime="temporary_session")` opens one fresh, headed Chromium in the selected Linux X11 desktop. The explicit lifetime is required: backend close, reconnect and MCP disconnect close the browser and delete its exclusive temporary profile, including unsaved documents, cookies and browser downloads stored there. Save required data outside that profile first. This is not an attachment mechanism for existing browsers, profiles or debugging endpoints.

The core provider supports ordinary HTML `input` types text/search/url/tel and `textarea`. `desktop_inspect` adds `text_fields` with distinct provider-bound element IDs. Use those IDs with `desktop_read_text`, `desktop_focus_element`, `desktop_select` and `desktop_type`; the ordinary accessibility `nodes` remain available for buttons and other native UI. IDs expire after 60 seconds and retain actual DOM node/document identity, not a selector to be resolved again. Navigation and replaced nodes invalidate them. Same-node application repurposing is not a general semantic identity guarantee.

Text offsets count Unicode code points. Selection uses a fixed selection-only browser operation; insertion uses Chromium `Input.insertText`, and clearing a selection uses browser-native Backspace. No DOM value setter or caller-supplied script is exposed. Ordinary HTML fields have no clipboard transport. Exact value readback verifies the HTML field value and reports caret verification separately; it does not establish application commit, autosave, formatting intent, keyboard-event handlers or autocomplete selection. Textareas preserve supported LF, tabs, blank lines, combining sequences and astral characters. Single-line fields refuse LF/tabs. CR/control-character rejection is unchanged.

Protected fields refuse ordinary text operations; observed password inputs reporting `secret_entry_supported:true` support [explicit dispatch-only secret replacement](OWNED-BROWSER-SECRET.md). Rich editors/contenteditable, frames and shadow-root fields are unsupported by this core text provider. Applications using ProseMirror can separately install [Editor Bridge](../addons/editor-bridge/README.md), which has its own tools, skill, browser session and application adapter. Installing core Luda does not install or enable it. A page containing frame elements is refused. Shadow roots are not traversed, and a previously observed light-DOM field moved into one is stale. A second page, changed browser window identity or changed display topology is refused. There is no arbitrary navigation/evaluation/protocol tool; use the visible browser UI for subsequent navigation.

## Provisioning

This capability is optional; default installation does not add Playwright or download a browser. From a trusted pinned source checkout, an operator can provision the exact `uv.lock` environment with `uv sync --locked --extra browser` and run that environment's `luda`. Configure `LUDA_CHROMIUM_EXECUTABLE` as an absolute executable path to an independently provisioned compatible Chromium. The tested pair is Playwright **1.63.0** and Chrome for Testing **153.0.8010.12** on Linux ARM64. Other browser/version pairs need qualification. No browser download or `--no-sandbox` fallback happens at runtime. The ordinary-account sandbox-enabled launch worked in this guest.

Managed installations can explicitly select browser support using [managed browser provisioning](MANAGED-BROWSER.md). The standard installation remains browser-free. A directly launched source-environment `luda` can use the explicit environment variable above; `luda-session` intentionally sanitizes ambient environment and instead reads the verified selection stored inside its managed release. Doctor's `owned_browser.available` reports dependency/executable presence, not successful launch or universal web compatibility. Launch failures are bounded and sanitized.

## Composition, focus and lifetime limits

A pre-document monitor records trusted composition events. Active or unknown composition is refused before focus, selection or typing. Chromium 153 can emit an untrusted composition end after real GTK preedit commits or cancels; that leaves the conservative monitor active. There is no automatic Escape, guessed commit or production recovery override. Deliberate document navigation establishes a fresh monitor, but can discard unsaved work. Existing native accessibility tools still have unknown composition state.

Owned-browser operations enable CDP document focus emulation so directly addressed DOM input can work while another application retains human keyboard focus. Element identity, active DOM element, composition and readback still require verification. Emulated document focus does not establish where native X11 keys will go: native input has separate routing and actual keyboard-focus validation. CDP field operations validate the native window identity and DOM focus without creating or focusing an independent keyboard. Native key actions automatically disable focus emulation and bring the owned page forward before checking real keyboard focus; later addressed field operations enable emulation again. This does not make GUI dispatch atomic: an application or human can change shared field selection between preflight and input. A historical independently injected focus race delivered text to another field and correctly returned `FOCUS_CHANGED` with uncertain effect; it is retained evidence of possible wrong-field effects, not a prevention claim. Never retry uncertain input automatically.

The owning guardian is a Linux subreaper. Commands have an eight-second owner deadline and a nine-second client deadline. Normal cleanup resumes an owned stopped guardian, closes its command lease, reaps owned descendants and clears the originally opened profile directory. A private proof pipe must confirm cleanup; missing proof produces `BROWSER_CLEANUP_UNCONFIRMED` and the same backend cannot open another owned browser. Root-directory replacement cannot redirect recursive deletion into the replacement. Client cleanup waiting is bounded and can remain unconfirmed; killing the guardian itself, kernel failure or hostile same-account interference is not a persistence guarantee. No unrelated Chrome processes are killed by name.

Readback is bounded to 64,000 code points/128,000 UTF-16 units; inspection examines at most 500 light-DOM fields and caches at most 1,000 provider handles. Protocol packets are bounded to 1 MiB. The browser itself is not a memory/CPU sandbox and can load resource-intensive pages. Its temporary-session lifetime is a deliberate tradeoff, not a persistent browser service.

## Native text input boundaries

The public offset unit remains Unicode code points. Chromium's native `Input.insertText` can normalize selections inside a grapheme only during input, even when DOM and application selection readback still show the exact requested offsets. It may append after a joined emoji/accented character or replace a whole grapheme outside the requested range. The retained [range prototype](PROSEMIRROR-SELECTION-PROTOTYPE.md) reproduces this in both rich editors and ordinary HTML fields.

Before focus, selection or native insertion/selected-range deletion, Luda now checks the intended endpoints using the browser's fixed [`Intl.Segmenter` grapheme mode](https://tc39.es/ecma402/#sec-intl.segmenter). Known interior endpoints return `UNSUPPORTED_TEXT_BOUNDARY` with effect none. Missing segmentation returns `TEXT_BOUNDARY_UNAVAILABLE`; no range is expanded or rewritten. Whole-field edges are known boundaries and need no segmenter, so complete replacements remain usable. The check is repeated before dispatch; the existing focus/content race limitations and post-input verification still apply. This is a refusal boundary for this transport, not universal grapheme-editing support or a change to read/selection offset units. It does not silently substitute deletion or clipboard paste.

The final ordinary-account private MCP run `run-1789890908181255632` passed in 14.603 seconds. Accent-only, interior emoji, collapsed interior caret and base-before-accent insertion requests preserve exact text and selection on refusal. The accent-only case also preserves a different field's actual focus. Complete combining-sequence and astral/emoji replacements still pass, along with the existing browser lifecycle tests. The rich regression passed in 22.394 seconds (`run-1789890793295876410`). The first new HTML test assertion incorrectly compared per-operation IDs across read responses and failed; that run is preserved, and the corrected oracle compares text/caret/selection and independently posted DOM state instead. Twenty-two focused browser/rich unit tests pass, including refusal before focus/select/input and missing-segmenter behavior.

A follow-up independently reproduced native Backspace expanding an interior emoji selection and deleting the whole emoji. Empty-text selected-range deletion now receives the same preflight and immediate-dispatch guard. Full-field clearing remains allowed; an empty collapsed request does not require segmentation. Actual private MCP run `run-1789891304330310696` passed in 15.927 seconds, including unchanged text/caret on interior emoji and accent deletion refusal and the existing full-field clear path. ## Automatic native compatibility

Owned-field type and selection use background CDP operations. Native shortcuts and IME actions in Chromium use automatic foreground input because the private XI2-only keyboard did not deliver the required events in the tested browser. Foreground focus is checked from the actual core keyboard, not only `_NET_ACTIVE_WINDOW`; MPX can leave that WM property stale. This is compatibility fallback, not private native Chromium qualification.
