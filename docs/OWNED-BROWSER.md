# Optional temporary owned browser

`desktop_open_browser(url, lifetime="temporary_session")` opens one fresh, headed Chromium in the selected Linux X11 desktop. The explicit lifetime is required: backend close, reconnect and MCP disconnect close the browser and delete its exclusive temporary profile, including unsaved documents, cookies and browser downloads stored there. Save required data outside that profile first. This is not an attachment mechanism for existing browsers, profiles or debugging endpoints.

The first production provider supports ordinary HTML `input` types text/search/url/tel and `textarea`. `desktop_inspect` adds `text_fields` with distinct provider-bound element IDs. Use those IDs with `desktop_read_text`, `desktop_focus_element`, `desktop_select` and `desktop_type`; the ordinary accessibility `nodes` remain available for buttons and other native UI. IDs expire after 60 seconds and retain actual DOM node/document identity, not a selector to be resolved again. Navigation and replaced nodes invalidate them. Same-node application repurposing is not a general semantic identity guarantee.

Text offsets count Unicode code points. Selection uses a fixed selection-only browser operation; insertion uses Chromium `Input.insertText`, and clearing a selection uses browser-native Backspace. No DOM value setter, caller-supplied script or clipboard paste is exposed. Exact value readback verifies the HTML field value and reports caret verification separately; it does not establish application commit, autosave, formatting intent, keyboard-event handlers or autocomplete selection. Textareas preserve supported LF, tabs, blank lines, combining sequences and astral characters. Single-line fields refuse LF/tabs. CR/control-character rejection is unchanged.

Protected fields, unregistered rich editors/contenteditable, frames and shadow-root fields are unsupported. Explicitly cooperating ProseMirror applications can use the [paragraph bridge](../integrations/prosemirror/README.md). A page containing frame elements is refused. Shadow roots are not traversed, and a previously observed light-DOM field moved into one is stale. A second page, changed browser window identity or changed display topology is refused. There is no arbitrary navigation/evaluation/protocol tool; use the visible browser UI for subsequent navigation.

## Provisioning

This capability is optional; default installation does not add Playwright or download a browser. From a trusted pinned source checkout, an operator can provision the exact `uv.lock` environment with `uv sync --locked --extra browser` and run that environment's `luda`. Configure `LUDA_CHROMIUM_EXECUTABLE` as an absolute executable path to an independently provisioned compatible Chromium. The tested pair is Playwright **1.63.0** and Chrome for Testing **153.0.8010.12** on Linux ARM64. Other browser/version pairs need qualification. No browser download or `--no-sandbox` fallback happens at runtime. The ordinary-account sandbox-enabled launch worked in this guest.

Managed installations can explicitly select browser support using [managed browser provisioning](MANAGED-BROWSER.md). The standard installation remains browser-free. A directly launched source-environment `luda` can use the explicit environment variable above; `luda-session` intentionally sanitizes ambient environment and instead reads the verified selection stored inside its managed release. Doctor's `owned_browser.available` reports dependency/executable presence, not successful launch or universal web compatibility. Launch failures are bounded and sanitized.

## Composition, focus and lifetime limits

A pre-document monitor records trusted composition events. Active or unknown composition is refused before focus, selection or typing. Chromium 153 can emit an untrusted composition end after real GTK preedit commits or cancels; that leaves the conservative monitor active. There is no automatic Escape, guessed commit or production recovery override. Deliberate document navigation establishes a fresh monitor, but can discard unsaved work. Existing native accessibility tools still have unknown composition state.

Playwright's default focus emulation is disabled before focus readback, so a DOM field cannot be considered focused merely because emulation says the document is active while the address bar receives native keys. This does not make GUI dispatch atomic: an application or human can change focus between preflight and input. An independently injected focus race delivered text to another field and correctly returned `FOCUS_CHANGED` with uncertain effect; it is retained evidence of possible wrong-field effects, not a prevention claim. Never retry uncertain input automatically.

The owning guardian is a Linux subreaper. Commands have an eight-second owner deadline and a nine-second client deadline. Normal cleanup resumes an owned stopped guardian, closes its command lease, reaps owned descendants and clears the originally opened profile directory. A private proof pipe must confirm cleanup; missing proof produces `BROWSER_CLEANUP_UNCONFIRMED` and the same backend cannot open another owned browser. Root-directory replacement cannot redirect recursive deletion into the replacement. Client cleanup waiting is bounded and can remain unconfirmed; killing the guardian itself, kernel failure or hostile same-account interference is not a persistence guarantee. No unrelated Chrome processes are killed by name.

Readback is bounded to 64,000 code points/128,000 UTF-16 units; inspection examines at most 500 light-DOM fields and caches at most 1,000 provider handles. Protocol packets are bounded to 1 MiB. The browser itself is not a memory/CPU sandbox and can load resource-intensive pages. Its temporary-session lifetime is a deliberate tradeoff, not a persistent browser service.

## Local evidence

`tests/live_owned_browser.py` runs actual MCP in an ordinary-account private Xvfb/XFWM/D-Bus session, with independent application HTTP oracles. Run it through `qualification_matrix.py --suites owned-browser --executable /absolute/chrome`. The first complete post-fix run `run-1789887558420559243` passed in 9.851 seconds: Unicode/LF/tabs/trailing blank lines, trusted native input events, astral selection replacement, protected refusal/redaction, replaced-node and navigation refusal, actual GTK-simple preedit refusal, frame refusal, disconnect cleanup, stopped-guardian cleanup, server SIGKILL cleanup and worker SIGKILL cleanup.

Earlier matrix runs remain under `artifacts/qualification-matrix/`: initial harness argument/action mistakes; incorrect focus call signature; actual focus-emulation failure (native keys reached the omnibox); and frame-cache staleness. These were not discarded or reclassified as successes. Independent review also reproduced stopped-guardian false cleanup and a root-replacement deletion race; the focused regression tests preserve both contracts. This scope does not qualify rich-text WEB-03/DATA-07 or every web application. The separate ProseMirror prototype and its failed formatting/composition routes remain evidence, not production support.

The expanded run `run-1789887774921463054` additionally verified empty whole-field replacement through native deletion and independently unchanged preedit after refusal: 10.395 seconds, unchanged source `b5ff26f798f77611336509a466cbd0b979c5c655dc897ad12ad1ee6dfc968b10`. Independent review repeated real Chromium cleanup with a stopped guardian: 15 exact owned process identities, 0.118 seconds, no survivors and profile removed. Actual built wheel and sdist contain `browser.py`, `_browser_guard.py` and `_browser_worker.py`; the fixed JavaScript is inline in those modules, with no missing external asset. Eleven focused browser tests pass; the broader pre-documentation branch run passed 698 tests. Skill synchronization into the Silo integration patch is a separate integration step.

Reconnect reports `browser_cleanup="confirmed"` or `"unconfirmed"` when it closes an owned browser; an unconfirmed cleanup makes the overall effect uncertain even though the desktop session switch succeeded. Twelve browser-specific tests and the existing reconnect tests pass together (28 checks). The final pre-reconnect-adjustment full branch run executed 699 tests with one preserved failure: the separately maintained Silo embedded skill had not yet been synchronized with the new optional-browser instructions.
