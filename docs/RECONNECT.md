# Reconnecting after a desktop restart

`desktop_reconnect(session_pid=None)` retargets the existing stdio MCP connection to one running XFCE session owned by the server account. If more than one exists, it returns their PIDs and requires an explicit choice. It checks the actual XFCE executable, process start identity, native display access and an answering session bus before replacing the backend. A missing session, failed probe, cancellation or busy peer preserves the current backend.

Reconnect refuses while another operation is active. It does not cancel an action, launch a desktop, restart applications or replay input. Status and pause/resume controls remain available. The selected display keeps its existing shared pause state; reconnect does not resume it. After success, observe again: prior window identities, elements and screenshot references expire. Run `desktop_doctor` to inspect accessibility and lock-state capabilities. An answering display and session bus do not prove accessibility registration, an unlocked screen, or application readiness. Existing applications may require their own recovery after accessibility-bus loss.

Each backend holds an immutable environment snapshot. Scoped subprocess environments route X11, accessibility, launched applications, clipboard ownership and the input-release companion to that backend without modifying the MCP process's global environment. Failed candidates release their resources; successful swaps release the old owned clipboard process and handles. Unrelated applications are never killed.

Selection is for ordinary same-account local XFCE sessions whose executable is `/usr/bin/xfce4-session`. Other desktop environments, foreign accounts, deleted/replaced session executables and incomplete sessions are not accepted. A same-account hostile X11 client or process is outside the isolation boundary. Session probes and overall operations remain deadline- and cancellation-bound; no probe can guarantee the desktop will remain alive after validation.

## Qualification

`tests/test_reconnect.py` covers session ambiguity/missing PID/process replacement, immutable nested environments, guarded preparation, cancellation, peer contention, same-display lock reuse, successful/failed backend swaps, bounded shutdown callbacks and independent companion cleanup environment. `tests/live_mcp_reconnect.py` uses two owned private Xvfb + D-Bus + actual XFCE sessions under the ordinary desktop account. One MCP connection survives terminating the original XFCE/display/bus, then reconnects, rejects old window/element/screenshot references, performs semantic Unicode editing and clipboard paste with independent GTK file readback, and preserves a paused replacement display. Neither test restarts or controls the user's desktop.
