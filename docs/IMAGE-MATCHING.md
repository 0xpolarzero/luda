# Historical screenshot image matching

`desktop_match_image(template_snapshot_id, template_bounds, snapshot_id, threshold=0.95, limit=20)` searches a selected source crop inside a retained target screenshot. Bounds are integer `{x,y,width,height}` in each screenshot's returned-image pixels. No filesystem image path, upload, automatic capture or input is accepted. Both screenshots must remain owned, cached and younger than 15 seconds. The source's X-server generation must still match; its old window layout may differ. The target's window, popup and display layout must still match before and after processing. Even when these checks pass, content can already have changed: results describe historical pixels only.

The optional engine is system Python OpenCV (`python3-opencv` on the tested Ubuntu distro), using its established [normalized correlation template matching](https://docs.opencv.org/4.x/d4/dc6/tutorial_py_template_matching.html). Nothing is downloaded at startup, and no mandatory installer dependency changes. Missing engine returns `MATCH_UNAVAILABLE` without changing backend readiness. OpenCV accepts negative correlation internally; a caller's finite threshold must be within 0–1. Scores are uncalibrated correlation, not probabilities, exact colors or semantic identity. Brightness differences may still correlate. Zoom, rotation, theme changes, text recognition and semantic matching are outside this contract. Different native-to-image scales are explicitly refused; templates are never silently rescaled.

Templates must be 8–512 pixels in each dimension and fit both images. A crop whose maximum spatial per-channel standard deviation is below 2/255 is refused as flat; differing RGB channels in a solid color do not constitute texture. Each screenshot is bounded to 2560² pixels and 32 MiB of PNG bytes; the combined encoded worker request is at most 33 MiB. The isolated worker has a 3-second caller deadline, one OpenCV thread, a 2-GiB address-space ceiling, and a four-second CPU limit. Cancellation reaps its process group. Output is limited to 64 KiB. PNG dimensions are checked before decoding; no persistent template store or extra screenshot cache is created.

Results are score-ranked non-overlapping placements. At most `limit+1` peak searches occur (`limit` is 1–100), without sorting all pixels or constructing a multi-million-item Python candidate list. Each accepted placement suppresses all overlapping positions. Thus nearby or overlapping instances can be omitted; separate identical icons remain separate results. `truncated=true` means another unsuppressed threshold-qualified peak remained when the output limit was reached. This is a bounded candidate proposal, never target authorization. Use ordinary observation and target checks before any independently requested input.
