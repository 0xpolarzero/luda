# Supervised click and wheel input

`pointer_input.click_button(button, count=1, target=None)` supports X11 buttons 1–7 and 1–20 repeats. The caller validates and positions the pointer and supplies the active owner XID. Native preflight refuses already held keys/buttons or latched keyboard state without releasing them. Caps/Num locks are preserved.

A companion owns the injection process. Cancellation or controller death stops and reaps that process, disconnects its nonce-identified X connection, then releases only the planned button. Injection and cleanup are bound to the original X-server generation. Restarting a server at the same display name cannot cause old cleanup to release input on its replacement. Incomplete cleanup blocks further input through the shared recovery registry; explicit input recovery uses each record's original environment and never replays clicks or wheel events.

Successful dispatch is not proof of an application action. Inspect the resulting UI. Concurrent human input can move the pointer or press the same planned button; X11 cannot attribute that shared button state. Preflight is a point-in-time check. Held drags use the same owned injector: the context yields only after native button-down confirmation, then normal exit, cancellation or controller EOF stops the worker before verified release. The guardian imposes a 30-second maximum hold. `check_pointer_ready(target=None)` provides a no-input preflight before initial movement or hover; callers must use it before moving, because moving with a human-held button can drag content.

`tests/live_pointer_guard.py` creates its own Xvfb, D-Bus session, private XDG directories, XFWM and GTK fixture. Independent application-file and XQueryPointer oracles verify triple clicks, vertical/horizontal wheel counts, refusal with an already held button, controller SIGKILL after a stopped injector has pressed a button, and cancellation mid-scroll without later events. This is synthetic native qualification, not universal application compatibility.

`tests/live_input_guard.py` independently verifies held-drag controller death with a stopped injector, injector reaping before release proof, cancellation and preheld-input preservation. The same-display restart test exercises the held-drag guardian and verifies old cleanup preserves matching held input on the replacement server.

## Generation-bound movement

Initial observation/preflight returns `server_generation`. Supply it to `move_pointer(x, y, server_generation, target=None)`; the isolated helper checks generation and held input on the same connection used for native motion. The server changing afterward disconnects that connection rather than retargeting it to a replacement display. Coordinates are bounded integers and must fit the current root dimensions.

Prefer `click_button(..., position=(x, y), server_generation=...)` to a separate initial move: the supervised injector validates state again before positioning and clicking. For dragging use `with held_button(button, server_generation=..., position=(x, y), target=xid) as pointer`, then `pointer.move(x, y)`. Each motion requires the original server, the owned button still down and no additional held keys/buttons. Releasing the button stops subsequent motion rather than turning a timed-out drag into hover. The pointer object expires when its context ends. Existing calls without optional arguments remain supported; callers operating from an observation should always supply its preflight generation.

Movement helpers use bounded subprocesses and one connection per step. This adds latency compared with raw XTest on a persistent connection; it keeps native-server failure outside the MCP process. Concurrent human changes after the preflight remain possible. The private restart test verifies both standalone and held-drag motion leave the replacement server's pointer position untouched.
