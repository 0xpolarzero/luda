# First-attempt terminal paste confirmation

One fresh Codex CLI attempt exercised **INTEL-06**: “Paste dialog: agent distinguishes blocked workflow from text loss.” The prompt asked for one exact multiline Unicode paste into Delivery receiver and verification without duplicate or extra input. It did not disclose a dialog, prescribe a tool sequence, or expose the oracle. Only the installed skill and public Luda tools were permitted; the retained trace contains a single permitted skill read and no source/oracle access, file mutations, launches, or other tools.

This was actual XFCE Terminal 1.1.3 with VTE 0.76.0 on Ubuntu 24.04 ARM64, ordinary UID 1001, private Xvfb/D-Bus/XDG. Its child was a passive raw PTY receiver, not a shell. The receiver does not know the expected payload, writes cumulative received bytes independently, and renders those bytes as a visible JSON receipt. Bracketed paste is explicitly disabled to expose the terminal's ordinary multiline confirmation. Terminal LF→CR conversion is checked exactly; the receipt labels its CR→LF rendering convention. No input is executed as a command.

## Reproduction and limits

Run `sudo .venv/bin/python scripts/agent_terminal_eval.py --timeout 180` only with explicitly authorized existing CLI authentication. It consumes model usage, creates a private ordinary-account desktop and temporary workspace, and does not modify global configuration or authentication. A separate preflight used deterministic public paste solely to verify fixture/dialog observability; it was not an agent attempt and did not tune the prompt. Four unit tests reject duplicates, extra Return, absent/late confirmation evidence, and promotion based on final agent prose.

This is one scoped first-attempt success, not an agent reliability rate, shell safety claim, browser clipboard qualification, other-terminal result, or macOS/Linux acceptance. Independent observation is separate X11/AT-SPI reads rather than an atomic event hook; if it misses the dialog or sees nonzero delivered bytes, the harness fails that criterion. The root CLI is instruction/trace constrained, not an adversarially isolated process unable to read its filesystem; actual trace inspection shows no fixture shortcuts used. No production runtime changed and no requirement is marked release-qualified.
